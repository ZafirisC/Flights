# CLAUDE.md — working rules for this repo

## Project
Flights: a static PWA flight tracker (see `SPEC.md`). Progress and next steps are in `PROGRESS.md`.
Read both at the start of every session. Do only the phase you were asked to do.

## Stack and conventions
- Vanilla JavaScript ES modules, no framework, **no build step**. Must run as plain files on GitHub Pages.
- Libraries from CDN with pinned versions only: Leaflet, Leaflet.markercluster.
- All UI text in **English**.
- One responsibility per file (`js/map.js`, `js/search.js`, …). Keep files small.
- **All network calls go through `js/api.js`.** No `fetch` anywhere else.
- `localStorage` access always inside try/catch.
- No API keys in the repo. If a key is ever needed, it lives in the Cloudflare Worker as a secret.
- `data/airports.json` is generated by `scripts/build_airports.py`. Never write or edit it by hand.

## Saving tokens
- Read only the files the current phase needs.
- Edit in place; do not rewrite whole files unless asked.
- Do not paste large file contents or logs into replies.
- Keep replies short: what changed, how to test, anything left open.
- At the end of each phase, update `PROGRESS.md` (status, decisions, known issues).

## Running locally
`python3 -m http.server 8000` in the repo root, then open `http://localhost:8000`.

## Tests
`node --test tests/*.mjs` (Node 22+, no dependencies). Covers the pure code in `js/progress.js` and the live-source
fallback chain / OpenSky parsing (OpenSky currently switched off) in `js/api.js` (fetch mocked).

## Reference
`reference/standalone.html` is an earlier single-file prototype (OpenSky + Leaflet). Reference only;
do not ship it and do not copy it wholesale.
